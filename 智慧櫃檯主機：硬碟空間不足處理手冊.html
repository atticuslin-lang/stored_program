硬碟空間不足處理手冊

智慧櫃檯 Ubuntu 主機

硬碟快滿了，一步一步把空間要回來

智慧櫃檯主機跳出「Filesystem root 只剩 942.5 MB」。系統所在的分割區快滿了，再滿下去程式會當機、更新會失敗、log 寫不進去，嚴重時甚至開不了機。

Filesystem root / 942.5 MB可用
已使用剩下的空間

手冊分成三個階段

  1. 診斷找出空間被誰吃掉，約 5 分鐘
  2. 修復從最安全的開始清，約 15 分鐘
  3. 預防設定自動清理與提早警告，約 20 分鐘
填一次，之後所有指令會自動帶入。在專案資料夾裡打 pwd 就能看到完整路徑。
請填完整路徑（以 /home 開頭），不要用 ~ 開頭。
使用方式

每個指令旁邊都有「複製」，貼到終端機按 Enter 即可。鍵盤 ← → 可以換頁，進度會記在這個瀏覽器裡。

所有可能的原因

不用全部讀完。先做診斷，診斷結果會告訴你該看哪一條；這頁是給你想先了解全貌時用的。

系統本身

  • 套件更新後留下的安裝檔（APT 快取）
  • 舊的 Linux 核心與沒人用的套件
  • 系統日誌（journal）沒有上限，一直長大
  • /var/log 裡的 syslog 被某個程式狂寫
  • Snap 自動保留好幾個舊版本
  • 程式當機留下的報告與 core dump
  • /tmp 暫存檔沒被清掉

智慧櫃檯與開發環境

  • 程式自己寫的 log 沒有輪替
  • 上傳檔、拍照、截圖、匯出檔不斷累積
  • node_modules、venv、建置輸出、npm 或 pip 快取
  • kiosk 瀏覽器的網頁快取
  • Docker 映像檔與舊容器

使用者檔案

  • 垃圾桶裡的檔案（刪除不等於釋放）
  • 縮圖快取與 ~/.cache
  • 下載資料夾、影片、備份檔等大檔案

看不見的佔用

  • 檔案已刪除，但程式還開著它，空間不會回來
  • Timeshift 系統快照越存越多
  • Flatpak 留下沒用的執行環境
  • 檔案數量太多，inode 用完（空間看起來夠卻寫不進去）

硬體與配置

  • 根分割區當初就切得太小

打開終端機，確認是哪裡滿了

先確定滿的是哪個分割區，後面才知道該清哪裡。

  1. 按 Ctrl + Alt + T 開啟終端機。
  2. 貼上這個指令：
df -h
你會看到

找「掛載於」欄位是 / 的那一行。「已用%」超過 90% 就是它。

檔案系統        容量  已用  可用 已用% 掛載於
/dev/sda2        30G   28G  943M   97% /
/dev/sda1       511M  6.1M  505M    2% /boot/efi

如果 /home 是另一個分割區而且沒滿，問題就出在系統資料夾（多半是 /var），不是你的個人檔案。

櫃檯在 kiosk 模式下叫不出終端機

按 Ctrl + Alt + F3 切到文字介面登入，做完按 Ctrl + Alt + F1 或 F2 回到畫面。也可以從另一台電腦連進來：

ssh 你的帳號@櫃檯主機IP
空間還有，卻一直說寫不進去

可能是 inode（檔案數量上限）用完了，常見於大量小檔案，例如 session 檔或縮圖。檢查：

df -i /

「IUse%」接近 100% 就是這個問題。用下面的指令找出哪個資料夾檔案最多，再到修復階段清掉對應的資料夾：

sudo find / -xdev -type f 2>/dev/null | cut -d/ -f2-4 | sort | uniq -c | sort -n | tail -n 15

找出最大的資料夾

從根目錄開始，一層一層往下找到吃空間的元兇。

sudo du -xh --max-depth=1 / 2>/dev/null | sort -h | tail -n 15
你會看到

由小排到大，最下面一行是總和，倒數第二行就是最大的資料夾。

1.2G    /snap
4.8G    /home
6.9G    /usr
14G     /var
28G     /

往下一層鑽

把指令裡的 / 換成最大的那個資料夾，重複幾次直到找到具體的東西：

sudo du -xh --max-depth=1 /var 2>/dev/null | sort -h | tail -n 15
怎麼判斷正不正常

/usr 在 5 到 10 GB 屬於正常，那是系統程式。/var 超過幾 GB，或 /home 大得不合理，通常就是問題所在。

想用圖形介面看

通知上的「Examine」按鈕就是磁碟用量分析器，會用圓餅圖顯示每個資料夾佔多少。如果想要在終端機裡用方向鍵瀏覽，可以裝 ncdu（只要幾百 KB）：

sudo apt install ncdu
sudo ncdu -x /

一次檢查所有常見嫌疑

這個指令會列出最常出問題的幾個地方各佔多少，對照下面的表就知道下一步。

journalctl --disk-usage
for p in /var/cache/apt /var/log /var/lib/snapd /var/crash /var/lib/systemd/coredump /var/lib/docker /tmp ~/.cache ~/.local/share/Trash "{{PROJ}}"; do sudo du -sh "$p" 2>/dev/null; done | sort -h

看結果，決定下一步

  • journal 或 /var/log 超過 1 GB
  • /var/cache/apt 超過 500 MB
  • /var/lib/snapd 超過 3 GB
  • ~/.cache 超過 1 GB
  • 專案資料夾很大
  • /var/crash 或 coredump 有東西
  • /var/lib/docker 很大
  • Trash 有東西

建議還是照修復階段的順序走一遍，每一步都很快，而且越前面越安全。這張表是讓你知道重點在哪。

找出「已刪除但還佔著」的檔案

檔案被刪了，但如果某個程式還開著它，空間就不會真的釋放。前面加總的數字和 df 差很多時，多半是這個原因。

sudo lsof +L1 2>/dev/null | awk 'NR==1 || $7 > 100000000'
你會看到

只有標題列：沒有這個問題，直接進入修復。
有列出檔案：記下第一欄程式名稱（COMMAND）和第二欄的 PID，到修復第 8 步處理。

COMMAND   PID  USER  FD  TYPE DEVICE   SIZE/OFF NLINK  NODE NAME
python3  1842  kiosk  3w  REG   8,2 2147483648     0 39120 /home/kiosk/.../app.log (deleted)

清空垃圾桶

在檔案管理員刪掉的東西只是搬進垃圾桶，空間沒有釋放。

gio trash --empty
你會看到

沒有任何輸出就代表成功。也可以直接按通知上的「Empty Trash」。

清空後無法復原，先確定裡面沒有你還要的檔案。

清掉 APT 快取與用不到的套件

每次系統更新都會留下安裝檔，舊的 Linux 核心也會一直堆著。

刪除下載過的安裝檔

sudo apt clean

移除舊核心和沒人用的套件

sudo apt autoremove --purge
你會看到

列出要移除的套件（常見的是 linux-image-… 舊核心），問你是否繼續，輸入 Y 按 Enter。

autoremove 不會移除正在使用的核心。想確認目前用的是哪個，執行 uname -r。

清單裡出現智慧櫃檯需要的套件

先輸入 n 取消，把那個套件標成手動安裝，再重新執行 autoremove：

sudo apt-mark manual 套件名稱

縮小系統日誌

日誌預設可以長到硬碟的 10%，某個程式出錯狂寫時會更快塞滿。

把 journal 縮到 100 MB

sudo journalctl --vacuum-size=100M

找 /var/log 裡超過 100 MB 的檔案

sudo find /var/log -type f -size +100M -exec ls -lh {} \;

清空正在使用的大 log（以 syslog 為例）

sudo truncate -s 0 /var/log/syslog

刪除已經輪替掉的舊 log

sudo find /var/log -type f \( -name "*.gz" -o -name "*.[0-9]" \) -delete
不要用 rm 刪正在寫入的 log

程式還開著它，空間不會回來，還會變成上一頁說的隱形佔用。用 truncate 清空內容才對。

syslog 一天就長好幾 GB

這代表有程式在不停寫錯誤訊息，清掉只是治標。看看是誰：

sudo tail -n 50 /var/log/syslog

如果一直重複同一個程式的錯誤，很可能就是智慧櫃檯或 kiosk 瀏覽器。修好那個錯誤，問題才會真的消失。

移除舊版 Snap

Snap 每個程式預設保留 3 個版本，Firefox、Chromium 這類大程式一個版本就好幾百 MB。

先關閉正在使用的 Snap 程式，例如 Firefox。

之後只保留 2 個版本

sudo snap set system refresh.retain=2

移除所有停用的舊版本

snap list --all | awk '/disabled/{print $1, $3}' | while read name rev; do sudo snap remove "$name" --revision="$rev"; done

清掉 Snap 下載快取

sudo rm -rf /var/lib/snapd/cache/*
你會看到

每移除一個版本會顯示一行「已移除」。沒有輸出代表本來就沒有舊版本。

清理使用者快取與瀏覽器快取

快取刪掉會自動重建，不會影響登入狀態或設定。kiosk 長時間開著網頁，瀏覽器快取常常長得很大。

看看 ~/.cache 裡誰最大

du -sh ~/.cache/* 2>/dev/null | sort -h | tail -n 10

清除縮圖快取

rm -rf ~/.cache/thumbnails/*

瀏覽器快取

先關掉 kiosk 瀏覽器，再執行你用的那一個。

Chromium（Snap 版）

rm -rf ~/snap/chromium/common/.cache/*

Firefox（Snap 版）

rm -rf ~/snap/firefox/common/.cache/*

Google Chrome

rm -rf ~/.cache/google-chrome/*

清理智慧櫃檯專案產生的檔案

程式寫的 log、上傳檔、截圖和開發產物，都可能在你沒注意時越長越大。

下面的指令會帶入這個路徑。
請填完整路徑（以 /home 開頭），不要用 ~ 開頭。
先備份，再刪資料

資料庫檔（.db、.sqlite）、使用者上傳、訂單或交易紀錄不要直接刪。先複製到隨身碟或雲端再處理。

1. 看專案裡誰最大

du -h --max-depth=2 "{{PROJ}}" 2>/dev/null | sort -h | tail -n 20

2. 找出超過 50 MB 的檔案

find "{{PROJ}}" -type f -size +50M -exec ls -lh {} \; 2>/dev/null

3. 清空過大的 log

先列出來看看：

find "{{PROJ}}" -name "*.log" -size +10M -exec ls -lh {} \;

確定要清空（程式正在執行也沒關係）：

find "{{PROJ}}" -name "*.log" -size +10M -exec truncate -s 0 {} \;

4. 清開發快取

這些都能重新產生，用到哪個執行哪個：

npm cache clean --force
pip cache purge
還可以刪的開發產物

以下資料夾都能用安裝或建置指令重新產生，但刪了之後程式要重新安裝相依套件才能跑：

  • node_modules：用 npm install 重建
  • .venv 或 venv：重新建立虛擬環境再 pip install -r requirements.txt
  • dist、build：重新建置
  • __pycache__：Python 會自動重建
上傳檔或截圖一直累積

先列出 30 天以前的檔案，只是列出，不會刪：

find "{{PROJ}}/uploads" -type f -mtime +30 -ls

資料夾名稱換成你實際存檔的地方。長期解法是在程式或排程裡設保留天數，預防階段會設定。

刪除當機報告與 core dump

程式每次當機，系統可能存下數百 MB 的記憶體快照。

先看看有哪些

ls -lh /var/crash /var/lib/systemd/coredump 2>/dev/null

刪除

sudo rm -f /var/crash/*.crash
sudo rm -f /var/lib/systemd/coredump/*
注意檔名

檔名會顯示是哪個程式當掉。如果一直是同一個（例如 python3、node、chromium），代表智慧櫃檯或 kiosk 瀏覽器在反覆當機，修好它才是根本解法。

釋放被程式佔著的空間

只有在診斷第 4 步有列出檔案時才需要做。重新啟動那個程式，空間就會回來。

查出這個 PID 屬於哪個服務

ps -o unit= -p PID

重新啟動那個服務

sudo systemctl restart 服務名稱

如果是你自己手動啟動的智慧櫃檯程式，關掉再重開就好。

最簡單的方法：重新開機

重開機會釋放所有隱形佔用，但櫃檯會中斷一兩分鐘，挑人少的時段：

sudo reboot

其他可能的大戶

前面都做完還是不夠，再展開符合你情況的項目。沒用到的可以跳過。

找出整台電腦超過 500 MB 的檔案
sudo find / -xdev -type f -size +500M -exec ls -lh {} \; 2>/dev/null

常見的有下載的 ISO 映像、影片、手動備份的壓縮檔。確認不需要再刪。

Docker

先看佔多少：

docker system df

移除停止的容器、沒用的網路和沒被標記的映像：

docker system prune

加上 -a 會連沒有容器在用的映像都刪掉，下次啟動要重新下載。如果你的智慧櫃檯跑在 Docker 裡，先確定它正在執行。

Flatpak
flatpak uninstall --unused
Timeshift 系統快照
sudo timeshift --list

保留最新的一到兩個就好，其他用 Timeshift 程式介面刪除，或：

sudo timeshift --delete --snapshot '快照名稱'
/tmp 暫存檔

刪除 3 天以上沒被讀取過的暫存檔：

sudo find /tmp -type f -atime +3 -delete

重開機通常也會清掉 /tmp。

確認清出了多少空間

回頭看第一步的指令，比較清理前後。

df -h /
目標

「已用%」降到 80% 以下，或至少留 5 GB 可用空間。

還是超過 90%

回到診斷第 2 步繼續往下找，或直接看預防第 7 步，硬碟本身可能就太小了。

限制系統日誌的上限

設好之後，journal 最多只會用 200 MB，舊的自動刪除。

sudo mkdir -p /etc/systemd/journald.conf.d
sudo tee /etc/systemd/journald.conf.d/size.conf >/dev/null <<'EOF'
[Journal]
SystemMaxUse=200M
SystemMaxFileSize=50M
EOF
sudo systemctl restart systemd-journald

確認生效

journalctl --disk-usage
你會看到

顯示的大小在 200 MB 以內。

讓智慧櫃檯的 log 自動輪替

每天換一個新檔、舊檔壓縮、只留 7 天，log 就不會無限長大。

下面設定檔會帶入這個路徑。如果 log 不在 logs 資料夾，記得改成實際位置。
請填完整路徑（以 /home 開頭），不要用 ~ 開頭。

建立輪替設定

sudo tee /etc/logrotate.d/smart-counter >/dev/null <<'EOF'
{{PROJ}}/logs/*.log {
    daily
    rotate 7
    compress
    delaycompress
    missingok
    notifempty
    copytruncate
}
EOF

試跑看看（不會真的動檔案）

sudo logrotate -d /etc/logrotate.d/smart-counter
你會看到

列出它找到的 log 檔和會做的動作，沒有 error 就完成了。系統每天會自動執行。

出現 insecure permissions 錯誤

在設定檔大括號裡加一行，帳號換成你的使用者名稱：

    su 你的帳號 你的帳號
在程式裡直接做輪替

也可以讓程式自己管理，效果一樣：

Python 用 logging.handlers.TimedRotatingFileHandler，設 when="midnight"、backupCount=7。

Node.js 用 winston-daily-rotate-file，設 maxFiles: "7d"。

兩種方法擇一，不要同時用，免得互相干擾。

讓系統自動清掉舊套件

設定自動更新時一併移除舊核心、每週清快取，Snap 只留 2 版。

sudo tee /etc/apt/apt.conf.d/52auto-cleanup >/dev/null <<'EOF'
Unattended-Upgrade::Remove-Unused-Kernel-Packages "true";
Unattended-Upgrade::Remove-Unused-Dependencies "true";
APT::Periodic::AutocleanInterval "7";
EOF
sudo snap set system refresh.retain=2
你會看到

沒有輸出就代表寫入成功。修復階段已經設過 Snap 的話，再設一次也沒關係。

設定每週自動清理

寫一個清理腳本，讓系統每週自動跑一次，就算你忘了也不會再塞滿。

A. 建立清理腳本

sudo tee /usr/local/bin/kiosk-cleanup.sh >/dev/null <<'EOF'
#!/bin/bash
apt-get clean
journalctl --vacuum-size=200M
find /var/crash -type f -mtime +7 -delete
find /var/lib/systemd/coredump -type f -mtime +7 -delete
find /tmp -type f -atime +7 -delete
# 智慧櫃檯上傳檔保留 90 天（確定要用再把下一行開頭的 # 拿掉）
# find "{{PROJ}}/uploads" -type f -mtime +90 -delete
EOF
sudo chmod +x /usr/local/bin/kiosk-cleanup.sh

B. 建立排程

sudo tee /etc/systemd/system/kiosk-cleanup.service >/dev/null <<'EOF'
[Unit]
Description=Weekly disk cleanup

[Service]
Type=oneshot
ExecStart=/usr/local/bin/kiosk-cleanup.sh
EOF

sudo tee /etc/systemd/system/kiosk-cleanup.timer >/dev/null <<'EOF'
[Unit]
Description=Run disk cleanup weekly

[Timer]
OnCalendar=weekly
Persistent=true

[Install]
WantedBy=timers.target
EOF

C. 啟用並確認

sudo systemctl daemon-reload
sudo systemctl enable --now kiosk-cleanup.timer
systemctl list-timers kiosk-cleanup.timer
你會看到

一行顯示下次執行時間（NEXT）的紀錄。想立刻跑一次測試：sudo systemctl start kiosk-cleanup.service

Persistent=true 讓主機在排程時間剛好關機時，下次開機會補跑。

空間快不夠時提早警告

每小時檢查一次，使用率超過 85% 就寫進系統紀錄，不用等到剩 1 GB 才發現。

A. 建立檢查腳本

sudo tee /usr/local/bin/disk-alert.sh >/dev/null <<'EOF'
#!/bin/bash
LIMIT=85
USE=$(df --output=pcent / | tail -n 1 | tr -dc '0-9')
if [ "$USE" -ge "$LIMIT" ]; then
  logger -t disk-alert "根目錄已使用 ${USE}%"
  # 想收到手機通知，可以在這裡用 curl 呼叫你的 webhook
fi
EOF
sudo chmod +x /usr/local/bin/disk-alert.sh

B. 每小時執行

sudo tee /etc/systemd/system/disk-alert.service >/dev/null <<'EOF'
[Unit]
Description=Disk usage check

[Service]
Type=oneshot
ExecStart=/usr/local/bin/disk-alert.sh
EOF

sudo tee /etc/systemd/system/disk-alert.timer >/dev/null <<'EOF'
[Unit]
Description=Hourly disk usage check

[Timer]
OnCalendar=hourly
Persistent=true

[Install]
WantedBy=timers.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now disk-alert.timer

C. 查看警告紀錄

journalctl -t disk-alert
讓智慧櫃檯自己顯示警告

你的程式可以定期讀取 df --output=pcent / 的結果，在管理後台顯示「硬碟空間不足」的提示。這樣負責櫃檯的人不用開終端機也會知道，比系統通知更不容易被忽略。

關掉 kiosk 用不到的東西

櫃檯機不需要一般桌機的除錯功能，關掉可以少很多默默累積的檔案。展開你需要的項目。

關閉當機回報（Apport）
sudo systemctl disable --now apport.service
sudo sed -i 's/^enabled=1/enabled=0/' /etc/default/apport

之後程式當機不會再產生 .crash 檔。開發除錯期間想看當機原因，可以先不要關。

不保存 core dump
sudo mkdir -p /etc/systemd/coredump.conf.d
printf "[Coredump]\nStorage=none\n" | sudo tee /etc/systemd/coredump.conf.d/kiosk.conf

只有安裝了 systemd-coredump 時才有作用，沒裝的話執行了也無害。

限制 kiosk 瀏覽器快取

Chromium 或 Chrome：在你啟動 kiosk 的指令後面加上這個參數，快取上限 100 MB：

--disk-cache-size=104857600

Firefox：網址列輸入 about:config，把 browser.cache.disk.capacity 設成 102400（單位 KB）。

長期：硬碟容量規劃

如果硬碟本身太小，清再多都只能撐一陣子。

看硬碟和分割區大小

lsblk -o NAME,SIZE,FSTYPE,MOUNTPOINT

建議

  • 根分割區在 32 GB 以下，對長期運作的櫃檯來說偏小。建議換成 64 GB 以上的 SSD。
  • 平常保持至少 20% 可用空間，系統更新才有餘裕。
  • 會一直成長的資料（上傳檔、照片、資料庫）放在獨立分割區、外接硬碟或雲端，這樣資料長大也不會拖垮系統。
硬碟還有沒分配的空間

lsblk 顯示的硬碟總容量比分割區加起來大很多，代表有空間沒用到。可以用 GParted Live USB 開機把根分割區擴大。

調整分割區有風險，一定要先完整備份，並在櫃檯不營業時進行。
